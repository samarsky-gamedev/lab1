# Объяснение программы

Вся программа — `main.py`, 200 строк. Читайте её сверху вниз: проверки,
объекты, хранилище и меню. Программа ведёт списки студентов, преподавателей
и курсов, а затем сохраняет эти списки в файл.

## Импорты и проверки — строки 1–16

`json` читает и записывает JSON. `Path` получает расширение имени файла.
`xml.etree.ElementTree`, сокращённо `ET`, работает с деревом XML.

`text(value)` проверяет, что значение — непустая строка, и убирает пробелы
по краям через `strip()`. При ошибке выполняет `raise ValueError(...)`.
`number(value)` принимает только целое число больше нуля. Проверка
`type(value) is int` также отклоняет `True`: в Python `bool` является
подклассом `int`, но логическое значение не подходит для ID или часов.

`value: str` — аннотация параметра, `-> str` — аннотация результата.
Они объясняют типы человеку и инструментам, но сами не проверяют данные.
Проверки выполняет код внутри функций. `-> None` означает отсутствие
содержательного возвращаемого результата.

## Пять классов предметной области — строки 19–49 и 59–146

1. `Person` — человек с именем `name`.
2. `Student(Person)` — студент: имя и группа `group`.
3. `Teacher(Person)` — преподаватель: имя и кафедра `department`.
4. `Course` — курс: название, часы и ID преподавателя.
5. `University` — коллекции этих объектов и операции над ними.

`__init__` вызывается при создании объекта. Например,
`Student("Иван", "ИДБ-25-01")` создаёт отдельного студента.
`self` — ссылка на этот конкретный объект; `self.name` — его поле.
`super().__init__(name)` вызывает конструктор `Person`, чтобы не повторять
проверку и присваивание имени в двух дочерних классах.

`__str__` определяет текст при `str(obj)` и выводе через `print`.
Один и тот же вывод работает со студентом, преподавателем и курсом,
но каждый класс формирует свою строку. Это пример полиморфизма.
Наследование показано классами `Student` и `Teacher`.

`UniversityError` — отдельный класс исключения, а не шестая сущность
университета. Он наследуется от встроенного `Exception`. Его создают для
понятных ошибок правил: повторный ID, отсутствующая запись, неверная связь.

## Как устроено хранилище — строки 56–71

`TYPES` связывает название раздела с классом: строке `students`
соответствует `Student`. Благодаря этому не нужны три копии одинаковых
операций. В `_records` находятся три словаря:

```python
{
    "students": {1: Student("Иван", "А-1")},
    "teachers": {1: Teacher("Анна", "Информатика")},
    "courses": {1: Course("Python", 72, 1)}
}
```

Внешний ключ — раздел, внутренний ключ — ID, значение — объект.
Студент и преподаватель могут иметь одинаковый ID: разделы разные.
Начальное подчёркивание `_records` обозначает внутреннее поле по соглашению
Python. Инкапсуляция здесь состоит в работе с записями через методы
`University`; это не строгий запрет доступа к полю или изменениям объекта.

`list_records` возвращает список пар `(ID, объект)` из `items()`.
`get` проверяет положительный ID и наличие записи, затем возвращает объект.
`Person | Course` означает, что допустим человек (в том числе его наследники)
или курс. Такая запись объединения типов требует Python 3.10+.

## CRUD — строки 73–90

CRUD — Create, Read, Update, Delete: создать, прочитать, изменить, удалить.

`put(kind, record_id, item, replace=False)` обслуживает создание и изменение.
Без последнего аргумента добавляет новый объект. С `replace=True` заменяет
уже существующий объект, сохраняя его ID. Это позволяет не дублировать
проверку типа и преподавателя.

Условие `exists != replace` проверяет допустимость операции:

| ID существует | replace | Результат |
|---|---|---|
| Нет | False | Добавить |
| Да | False | Ошибка: ID занят |
| Нет | True | Ошибка: ID не найден |
| Да | True | Изменить |

Для курса метод вызывает `get("teachers", item.teacher_id)`: если
преподавателя нет, выполнение прервётся до записи объекта в словарь.
`delete` тоже сначала проверяет наличие записи. При удалении преподавателя
`any(...)` проверяет, ссылается ли на него хотя бы один курс. Если да,
возникает исключение; иначе `del` удаляет запись. В цикле `for _, c`
подчёркивание означает, что ID курса не нужен, используется только объект.

## Сохранение — строки 92–110

`vars(item)` получает словарь полей объекта. Например,
`vars(Student("Иван", "А-1"))` даст `{"name": "Иван", "group": "А-1"}`.
Запись `{"id": i, **vars(item)}` добавляет ID к этим полям.
`**` здесь распаковывает содержимое словаря. Генераторы списков и словарей
собирают все записи без промежуточных переменных и отдельных циклов на раздел.

Для `.json` выполняется `json.dump`. `ensure_ascii=False` сохраняет русские
буквы читаемыми, `indent=2` добавляет отступы. `with open(...)` гарантирует
закрытие файла после выхода из блока, включая выход из-за исключения.

Для `.xml` создаётся дерево: `university` → раздел → `record` → поля.
`SubElement` создаёт вложенный тег. XML хранит текст, поэтому числа
преобразуются через `str`. `ET.indent` оформляет отступы, `write` записывает
дерево в UTF-8 с XML-декларацией. Специальные символы экранирует библиотека.

## Загрузка — строки 112–146

`json.load` получает словари и списки из JSON. Для XML `ET.parse` читает
дерево, а `getroot` возвращает корневой элемент. Поля `id`, `hours` и
`teacher_id` преобразуются обратно в `int`. Проверяются корень, разделы,
вид записей, отсутствие вложенных и повторяющихся полей.

Далее оба формата проходят одну проверку. В данных должны быть именно
`students`, `teachers`, `courses`, каждый раздел — список, каждая запись —
словарь с ID. Сначала загружаются преподаватели, потому что курсы ссылаются
на них. Студенты и курсы загружаются после этого.

`row.copy()` создаёт копию словаря; `pop("id")` извлекает и удаляет ID.
`TYPES[kind](**fields)` вызывает нужный конструктор с именованными
аргументами. Для студента это равносильно `Student(name=..., group=...)`.
Конструктор проверяет поля, а `put` — ID и связи. Лишнее или отсутствующее
поле вызывает `TypeError` при вызове конструктора.

Все объекты сначала попадают во временный `loaded`. Только последняя строка
заменяет `_records`. Поэтому ошибка даже в последней записи не уничтожит
текущие данные. Корректная загрузка заменяет все разделы, а не объединяет их.

## Ввод и меню — строки 149–200

`read_item(kind)` спрашивает поля нужного объекта и вызывает его
конструктор. `input` всегда возвращает строку; для чисел нужен `int`.

`main` создаёт один университет. `while True` повторяет меню. Действие
определяется через `if/elif/else`. `break` завершает цикл; `continue`
после просмотра списка возвращает к его началу без сообщения «Готово».

Действия 5 и 6 работают с файлом. Для остальных выбирается раздел, затем
вводится ID и при необходимости поля. При изменении вводятся все поля,
а не только одно изменяемое значение. Выражение `replace=action == "3"`
передаёт `True` только для действия «Изменить».

Блок `try` охватывает одно действие. `except` перехватывает собственное
исключение, ошибки значений/типов/ключей, ошибки файлов и разбора XML.
`JSONDecodeError` наследуется от `ValueError`, поэтому тоже перехватывается.
Сообщение печатается, затем цикл продолжается. `EOFError` и
`KeyboardInterrupt` означают завершение ввода или Ctrl+C; в этих случаях
программа выходит без трассировки ошибки.

Последняя конструкция `if __name__ == "__main__": main()` запускает меню
только при прямом запуске файла. При `import main` классы доступны другим
программам и проверкам, но меню не стартует.

## Как показать работу на защите

1. Запустите `python main.py`.
2. Выберите 6 и загрузите `examples/university.json`.
3. Через 1 покажите студентов, преподавателей и курсы.
4. Через 2 добавьте студента с новым ID, через 3 измените его группу.
5. Попробуйте удалить преподавателя 1: программа покажет ошибку из-за курса.
6. Удалите новый объект студента через 4.
7. Через 5 сохраните данные в `data.xml`; откройте файл текстовым редактором.
8. Через 6 загрузите `data.xml` и снова покажите списки.
9. При вводе ID введите `abc`: ошибка будет обработана, меню появится снова.
10. Сохраните нужные данные и завершите работу через 0.

Новый файл без загрузки начинается с пустых списков. Автосохранения нет.
Списки записей на курсы, оценки, даты рождения и учёт успеваемости не входят
в эту небольшую модель.

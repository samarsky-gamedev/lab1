# Краткие ответы к защите

1. **Прикладное программирование** — создание программ для задач
   пользователя: учёта, расчётов, обучения, обработки документов.
2. **Разработка прикладного ПО** начинается с требований и модели данных;
   затем создают интерфейс и логику, проверяют результат и сопровождают код.
3. **Компиляция и интерпретация.** Компилятор переводит программу в другой
   код до исполнения; интерпретатор исполняет её через свою среду.
   C обычно компилируют в машинный код. CPython сначала компилирует Python
   в байткод, который выполняет виртуальная машина. Язык и способ его
   реализации не следует считать одним и тем же.
4. **Статическая и динамическая типизация.** В Java типы выражений проверяют
   до выполнения; в Python тип связан с объектом и проверяется во время
   работы. Аннотации Python сами по себе не вводят статическую проверку.
5. **Строгая и слабая типизация.** Термины не имеют единого строгого
   определения. Обычно Python называют строго типизированным: `1 + "2"`
   вызывает ошибку. JavaScript допускает больше неявных преобразований:
   `1 + "2"` даёт строку `"12"`.
6. **Уровень языка.** Высокоуровневые языки (Python) скрывают детали памяти
   и процессора; низкоуровневые (ассемблер) близки к инструкциям машины.
7. **Изменяемые типы:** list, dict, set. **Неизменяемые:** int, float, bool,
   str, tuple. Неизменяемый кортеж может содержать изменяемый список.
8. **Базовый синтаксис:** присваивание `=`, сравнения `==`, `<`, логические
   `and/or/not`; ветвление `if/elif/else`; циклы `for/while`; функции `def`.
   Блоки выделяются отступами.
9. **ООП:** класс описывает структуру и поведение, объект — экземпляр класса.
   Инкапсуляция объединяет данные с методами и задаёт границы доступа;
   наследование расширяет родительский класс; полиморфизм позволяет выполнять
   одинаковую операцию над разными объектами с разным поведением.
10. **`*args` и `**kwargs`:** в параметрах функции собирают дополнительные
    позиционные аргументы в кортеж и именованные — в словарь. При вызове
    `*values` и `**fields` распаковывают коллекции в аргументы.
11. **Лямбда:** небольшая функция-выражение, например `lambda x: x * 2`.
    Удобна как короткий ключ сортировки: `key=lambda item: item.name`.
12. **Аннотации:** `def square(x: int) -> int:` описывает ожидаемый аргумент
    и результат. `list[str]` — список строк, `str | None` — строка или None.
13. **PEP 8:** рекомендации по стилю: отступы по 4 пробела, понятные имена,
    `snake_case` для функций и переменных, `CapWords` для классов,
    пробелы вокруг операторов, умеренная длина строк.
14. **Ошибки:** синтаксические мешают разбору программы; ошибки выполнения
    часто выражаются исключениями; логические дают неверный результат без
    обязательного падения. Примеры: SyntaxError, ValueError, TypeError.
15. **Обработка исключений:** `try` содержит потенциально опасную операцию,
    `except` обрабатывает подходящее исключение; `else` выполняется без
    исключения в try; `finally` — при выходе из конструкции.
16. **Иерархия:** BaseException — корень; Exception — база большинства
    обычных ошибок. Примеры: ValueError, TypeError, KeyError, IndexError,
    ZeroDivisionError, OSError, FileNotFoundError. KeyboardInterrupt
    не является наследником Exception и обрабатывается отдельно.
17. **Собственное исключение:** `class UniversityError(Exception): ...`.
    Создание ошибки: `raise UniversityError("ID занят")`.
    Перехват: `except UniversityError as error: print(error)`.
18. **XML:** текстовый формат дерева тегов и атрибутов. Сериализация —
    перевод объектов в это представление; десериализация — восстановление.
    В программе используются ElementTree, Element, SubElement, parse, write.
19. **JSON:** текстовый формат объектов, массивов, строк, чисел,
    true/false/null. `dump/load` работают с файлом, `dumps/loads` — со строкой.
    Произвольный объект класса сначала преобразуют в словарь.
20. **XML и JSON:** оба формата переносимы и читаемы человеком. JSON обычно
    компактнее для структурированных данных и различает базовые типы.
    XML использует теги, поддерживает атрибуты, пространства имён и смешанное
    содержимое; при обычном разборе текст числовых полей нужно преобразовать.

Для этой лабораторной важно самостоятельно уметь объяснить `super`, `self`,
`put(..., replace=True)`, `vars`, `**fields`, временный объект при загрузке
и продолжение цикла после `except`.
